Mandate: likeness and voice consent vocabulary

Version 1.1.1 · Namespace https://oojae.github.io/mandate/ns/v1# · Apache-2.0

A vocabulary for publishing consent to render a person's likeness or voice, revoking it, and recording what was produced under it — so that the party who grants permission, the party who renders, and a third party who trusts neither can all reach the same verdict from the same graph.

The authorship rule. Authorship is the address that anchored a Knowledge Asset, never a value written inside it. A mandate:LikenessGrant counts only when anchored by the address in its mandate:subject; a mandate:GrantState counts only when anchored by the address that anchored its grant. The graph is append-only and anyone can write mandate:grantor or mandate:stateAuthor naming anyone, so a resolver that trusts those values lets the party that profits from rendering invent a grant or defeat a revocation. Version 1.0.0 made that mistake.

Likeness grant

LikenessGrant

https://oojae.github.io/mandate/ns/v1#LikenessGrant

Permission, published by the depicted person's own agent, to render their likeness or voice with named capabilities, for named uses, in named territories, within a validity window and a spend ceiling. A resolver MUST accept a grant only from the Knowledge Asset anchored by the address its mandate:subject names, and that address must also be the one in mandate:grantor. Identifies its subject by a declared identifier, never by biometric data.

grantor

https://oojae.github.io/mandate/ns/v1#grantor

The agent DID of the grantor, did:dkg:agent:0x<address>. Descriptive: a resolver checks it against the address that anchored the grant and rejects the grant if they differ.

subject

https://oojae.github.io/mandate/ns/v1#subject

A declared identifier for the depicted person, of the form 0x<grantor address>:<name>, so only that address can grant or revoke for it. Never derived from biometric data. Every grant and derivation linked to a subject is public and permanent, so the name should be meaningless outside the relationship.

consentClipSha256

https://oojae.github.io/mandate/ns/v1#consentClipSha256

Hex SHA-256 of the recorded consent clip. The clip itself is never published to the graph. The reference CLI writes it only when the transcript is a reading of the consent script it generated from the grant’s own terms, with nothing contradicted. A grant whose clip an operator confirmed by hand, with or without --force, carries no clip hash, and so does a grant made without a clip.

Start of the validity window, an xsd:dateTime with an explicit Z or ±hh:mm offset. Absent means no start. A value that is not a real date and time is refused by the gate and verifies TAINTED with sub-status MALFORMED.

validUntil

https://oojae.github.io/mandate/ns/v1#validUntil

End of the validity window, an xsd:dateTime with an explicit Z or ±hh:mm offset, later than mandate:validFrom. Absent means no end. After it, new renders are refused, and a file rendered inside the window verifies TAINTED with sub-status EXPIRED: the grant lapsed, which is not a withdrawal of consent.

maxSpendUsd

https://oojae.github.io/mandate/ns/v1#maxSpendUsd

Ceiling in US dollars on spend across renders authorised by this grant, summed from mandate:billedUsd on the derivations of trusted producers in the derivations graphs the gate reads. Enforced by the producer’s own gate before dispatch, in whole micro-dollars: prior spend and the estimate rounded up, the ceiling rounded down. An unknown cost, or an unreadable record from a trusted producer, under a ceiling is refused. Not a platform limit.

Grant state assertion

GrantState

https://oojae.github.io/mandate/ns/v1#GrantState

An append-only assertion that a grant is revoked. Because the graph has no delete, assertions accumulate and anyone can write one. A state assertion counts only when the Knowledge Asset holding it was anchored by the same address that anchored the grant it refers to. Revocation is terminal: any counted revocation ends the grant for good, an “active” assertion has no effect, and renewing consent means publishing a new grant.

stateOf

https://oojae.github.io/mandate/ns/v1#stateOf

The grant this state assertion is about. Exactly one grant IRI. Once it names a grant anchored by the same address that anchored this assertion, the assertion counts as a revocation even if its other values are malformed, and even if the same object is also typed as a grant or a derivation.

mandate:GrantState
range

state

https://oojae.github.io/mandate/ns/v1#state

“revoked”. Any other value is treated as revoked by a fail-closed resolver; “active” has no effect.

domain
mandate:GrantState
range
xsd:string

stateAuthor

https://oojae.github.io/mandate/ns/v1#stateAuthor

The agent DID that wrote this state assertion. Descriptive only: anyone can write any DID here. A resolver MUST attribute a state assertion to the address that anchored its Knowledge Asset, and count it only when that address anchored the referenced grant. A stateAuthor that disagrees with the anchoring address makes the assertion malformed, and a malformed assertion by the grant’s own publisher still counts as a revocation. Version 1.0.0 of this vocabulary compared this value instead, which let a forger name the grantor.

Derivation

Derivation

https://oojae.github.io/mandate/ns/v1#Derivation

A record of one produced artifact, identified by the SHA-256 of its bytes, linking it to the capability that served it and the grant that authorised it. Each derivation has its own IRI. Written and anchored before the artifact is released, so that revocation can enumerate everything produced under a grant. A verifier judges a file only by derivations anchored by producers it trusts.

outputSha256

https://oojae.github.io/mandate/ns/v1#outputSha256

Hex SHA-256 of the produced artifact's bytes. The key a third party verifies against.
